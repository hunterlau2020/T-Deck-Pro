- `esp_ota_mark_app_valid_cancel_rollback()` 是真实存在的 ESP-IDF API
  （`esp_ota_ops.h`），语义正确：把当前 `ESP_OTA_IMG_PENDING_VERIFY`
  状态的 slot 标记为有效，取消回滚——用法与设计描述吻合。
- `http_apply_tls()` / `http_ensure_time()` 在 `http_utils.cpp` 中确有

  `WiFiClientSecure` 这一点与 arduino-esp32 该库的公开接口相符，方案

## 建议改为 v1 必做（原列为二期/可选）

### 清单（manifest）不做签名校验的风险接受度——建议至少加 SHA256（§8.4）

设计稿把"依赖 HTTPS 传输安全"作为唯一防线，SHA256 字段标注"本版不
实现"、ed25519 签名列为二期。SHA256 校验的成本很低（清单里加一个字段，
下载完后算一次哈希），但收益不只是"防服务器被攻破的供应链攻击"这一
档——它还白捡了"防坏包/CDN 传输损坏/清单与实际 bin 不匹配"这一档，
而这恰好是 §5 三层防护模型里"第 1 层：下载中断/坏包"目前**只靠
HTTPUpdate 内部的 Content-Length/流式写校验**兜底的地方。建议 v1 就把
manifest 的 SHA256 字段做上（清单里加 `"sha256": "..."`，`ota_run` 下载
完在写入 flash 前后接 `esp_rom_md5`/自行算 SHA256 或复用
`Update.h` 自带的 MD5 校验能力），ed25519 签名可以留二期不变。

### 生产模式禁明文——建议同时覆盖 manifest 和固件 bin 两个 URL（§8.3）

设计稿 §8.3 只讨论了"固件下载 URL"要不要强制 HTTPS，但**清单本身**如果
允许明文 HTTP 拉取，攻击者/中间人只要能改写清单响应体，就能把
`url` 字段指向任意地址（哪怕那个地址本身是 `https://`），清单是"决定
下载源"的那一步，比固件下载 URL 更值得保护。建议实现时那个"默认禁
明文"的编译期开关同时挡住 `ota_fetch_manifest()` 和 `ota_run()` 两处
的 `http://` 前缀判断，不要只挡后者。

## 建议补充到 §7 验证计划

新固件 `setup()` 中途**挂死但没有 panic/reset**（例如某个外设初始化
死等，不是崩溃）——这种情况下自证点 `esp_ota_mark_app_valid_cancel_
rollback()` 永远不会被调用到，但如果设备也没有真的复位（比如任务
看门狗没有覆盖到 `setup()` 阶段，或者看门狗超时时长比用户等待时间长），
bootloader 的回滚判定逻辑（在下一次真实重启时才生效）就没有机会跑，
设备会一直卡在"能力上应该回滚、但实际没有触发"的悬空状态，而不是
干净地表现为"这次升级失败、变砖"或"已回滚"两种设计里讨论过的结局。
这是 §5 三层模型和 §7 反向用例目前都没有覆盖的第三种失败形态（"挂但
不重启"，介于层 1 和层 2 之间）。建议：
1. 确认 Arduino-ESP32 在这块板子上默认开启的任务看门狗超时时间，以及
   它是否覆盖 `setup()`（不只是 `loop()`）；
2. 在 §7 反向用例里加一条：新固件里临时塞一个 `setup()` 死循环（不
   panic、不喂看门狗），真机验证究竟是看门狗兜底触发复位（进而在下次
   启动时被 bootloader 判定回滚）、还是真的会卡死不动——把结论记录进
   issue_list，作为这套自证机制的已知边界。

## 建议顺带处理的实现细节

- 沿用本轮 `721e04a`（PenPal LVGL 48K→64K 池扩容）刚验证过的教训：
  新的 OTA 设置屏（§4，含状态展示、Check/Update 按钮、进度覆盖层、
  确认对话框）会往同一个 `LV_MEM_SIZE` 静态池里加控件。当前池余量约
  17K，看起来够用，但这正是上一次"看起来够用直到不够用"的同一类
  资源。建议在 `ota_update`/OTA 屏幕的 `create()` 和进度覆盖层首次
  弹出处，照 `pp_dbg_pool()` 的样子打一行 `[PD]`-风格水位日志（哪怕只
  是临时性、验证完再降级为条件编译），比事后再抓一次三轮 bisect 便宜
  得多。

## 未改变结论的既有取舍（无异议）

- 不做自动强更、手动触发——同意，OTA 场景下用户可控优先于便利性。
- 自证点选在 `setup()` 末尾而非"WiFi 连上后"——同意，避免网络质量把
  好固件拖入回滚循环的理由成立。
- 用 `HTTPUpdate` 而非 `esp_https_ota` 组件——同意，Arduino 生态下前者
  与现有 `HTTPClient` 风格一致，维护成本更低，行为等价。
- 版本比对用字符串不等（不做 semver 大小判断）——同意，避免版本号格式
  不统一导致误判，且与"手动决定是否更新"的整体设计一致。
