## 自评最没把握的点（请重点击穿）

1. **`lt_stair_step` 对 `grade_staircase` 的转录**（v1.17 核心）：连对 2 升级 / 连错 2
   降级 / 最多 2 次降级 / 16 答封顶。已做对拍验证（设备逻辑转录 Python，20000 组随机
   序列，终止判定与消费数 0 偏差）——但**请独立重推一遍**，尤其：封顶检查在连击
   检查之后（第 16 答同时是登顶时应报登顶而非封顶）；地板终止不递增 `downs`；
   `s_ans_n` 先记后步（消费数含触发终止的那一答）。
2. **exclude 列表封顶**：设备缓冲 1990 解码字节 vs 服务端 `max_length=2000`；超出即
   停止追加（重复题合法）。论证：16 题 × 最长题干 100B × URL 编码膨胀不出界？
   （编码后长度服务端不校验，校验的是解码值——请确认这个读法。）
3. **中途拉题失败策略**（有意偏离范例）：重试一次后放弃且**不提交**——范例的模拟
   学生循环会盲答续推。产品理由：真人无法作答没拉到的题。请评估该偏离是否会在
   "某级别题库恰好空（404 永久）"部署下把测试变成永远无法完成。
4. **`s_enter_pending`**：置位仅在请求在飞 + 非 QUIZ 页；触发在 poll 顶部且触发即清。
   双击 Enter 快速连按会否造成二次 `lt_start`？`lt_session_reset` 清位的完备性
   （entry 路径 vs RESULT 页重测路径）。
5. **字库覆盖方法论**：全集 = 21311 词 `meaning_zh` 全串并集（非首义、非抽样）+ 语法
   题库源码字符 + 常用标点；IPA `ː` 与 1 个 PUA 字符有意不含。生成后回读 .c 的
   `U+XXXX` 清单对账 0 缺字。风险：题库后续增长超集 → 缺字（TODO 有重生成指引）。
6. **答案 level 上报**：设备报 `LT_ORDER[s_st_idx]`（机器自身视图）而非 `s_cur.level`
   （服务端回显）。服务端 `grade_staircase` 声明 level 仅作展示、转移以机器自身状态
   为准——两口径在设备上应恒等，请确认无分叉窗口（如拉题后、作答前 idx 已变？）。
7. **v1.13 遗留面**：菜单 `page` 字段分组（21 入口 6/7/8）与 `page_num=max(page)` 的
