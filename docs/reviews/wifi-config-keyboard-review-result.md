# WiFi 配置交互重设计与键盘布局修正评审结果

- **评审日期**：2026-08-15
- **评审申请书**：[wifi-config-keyboard-review-request.md](wifi-config-keyboard-review-request.md)
- **关联分支**：`HD-V2-250915`
- **评审范围**：工作区未提交的 `examples/pda2/peri_keypad.cpp`、`ui_deckpro.cpp`、`ui_ai_chat.cpp`、`README.md`
- **评审结论**：**退回修订**

## 1. Findings

### 1.1 `+`、`-` 被无条件占用，合法 SSID 无法手动输入

- **严重性**：Medium
- **位置**：`examples/pda2/ui_deckpro.cpp:1624-1634`
- **触发场景**：手动输入 `Home-5G`、`AP+Guest` 等包含 `-` 或 `+` 的 SSID。
- **证据**：SSID 字段收到 `+` 或 `-` 后始终进入扫描结果切换分支；即使没有扫描结果，也只显示 `"Enter: scan first"`，不会把字符加入文本框。
- **影响**：本次重设计的核心目标“允许手动输入任意 SSID”未完整实现，用户会保存并连接到错误的网络名。
- **最小修复**：增加明确的“手动编辑/扫描选择”状态。仅在扫描选择状态拦截 `+`、`-`；一旦用户开始编辑，所有可见字符均应写入文本框。

### 1.2 已保存 SSID 时扫描入口不可达，界面提示与实际行为不一致

- **严重性**：Medium
- **位置**：`examples/pda2/ui_deckpro.cpp:1609-1623,1708-1721`
- **触发场景**：NVS 中已有 SSID，进入 WiFi Config 后直接按 Enter。
- **证据**：`wifi_cfg_refresh()` 会把已保存 SSID 填入文本框；Enter 仅在文本框为空时扫描，非空时直接进入密码字段。界面却统一提示 `"Enter=scan"`。
- **影响**：常见的“从旧网络切换到新网络”场景必须先逐字删除旧 SSID 才能扫描，用户很容易误以为扫描功能失效。
- **最小修复**：提供不依赖文本框是否为空的独立扫描操作，或设计清晰的编辑/扫描模式并同步更新提示。不能继续用“空值”同时承担用户数据和交互模式判断。

### 1.3 三个 Shift 共用单一布尔值，组合按键释放顺序会产生错误状态

- **严重性**：Medium
- **位置**：`examples/pda2/peri_keypad.cpp:133-137`
- **触发场景**：按住左 Shift，再按住右 Shift，释放左 Shift 后继续输入字母。
- **证据**：任意 Shift 的释放事件都会执行 `shift_active = false`，没有保留其他 Shift 仍按下的状态。
- **影响**：仍按住 Shift 时可能输出小写；在事件延迟或丢失时也更难恢复正确状态。
- **最小修复**：分别记录三个修饰键的状态，或使用三位位掩码；实际 Shift 状态取各键状态的逻辑 OR。

### 1.4 同步扫描会阻塞键盘取事件，评审申请对“不丢事件”的判断不成立

- **严重性**：Medium
- **位置**：`examples/pda2/ui_deckpro.cpp:1531-1534,1618-1622`、`examples/pda2/peri_keypad.cpp:101-151`
- **触发场景**：`WiFi.scanNetworks()` 阻塞 2–4 秒期间快速按键，或按下/释放 Shift 并继续输入。
- **证据**：
  - `WiFi.scanNetworks()` 在主循环内同步执行，期间 `keypad_loop()` 不会运行。
  - TCA8418 只有 `KEY_EVENT_A` 至 `KEY_EVENT_J` 共 10 个事件寄存器。
  - 当前驱动每次主循环只读取一个事件，也没有检查 `OVR_FLOW_INT`。
- **影响**：超过 FIFO 容量后可能丢失按下或释放事件；若丢失 Shift 释放事件，`shift_active` 会持续卡住。因此申请书 §5.4 中“键盘事件排队不丢失、无残留风险”的结论不成立。
- **最小修复**：优先改用异步 WiFi 扫描，使主循环持续排空键盘 FIFO；同时每轮读取完所有待处理事件，并增加溢出检测及修饰键状态恢复策略。

### 1.5 扫描失败与“未发现网络”被合并，无法定位自动重连冲突

- **严重性**：Low
- **位置**：`examples/pda2/ui_deckpro.cpp:1533-1542`
- **触发场景**：扫描 API 返回负数错误，而非返回 0 个网络。
- **证据**：所有 `n <= 0` 均显示 `"Scan: none found"`。
- **影响**：用户和日志无法区分附近确实没有网络、扫描正在运行或扫描失败；申请书 §5.3 所述自动连接冲突也无法被验证。
- **最小修复**：分别处理 `n == 0` 和 `n < 0`，显示或记录错误码。不要默认在每次扫描前无条件 `WiFi.disconnect()`；仅在确认连接状态导致扫描失败后再实施暂停重连和恢复策略。

## 2. 设计决策答复

| 申请项 | 评审意见 |
|---|---|
| §5.1 Alt 语义 | 建议采用 **B：Alt 作为按住生效的临时符号层**。用户原始问题包含“Alt 变成 Shift”，当前方案仍保留该行为，不能算完全修复。若产品决定采用 A，需明确记录这是有意行为而非硬件映射。 |
| §5.2 `\b` 空框返回 | **接受现有约定**：有字删除、空框返回，并在页面提示 `Backspace=del/back`。保留纯键盘返回路径。 |
| §5.3 扫描与自动连接 | **不接受无条件断开**。先区分扫描错误码并完成真机验证；实现异步扫描后，如仍可复现冲突，再在配置页生命周期内暂停自动重连并在退出时恢复。 |
| §5.4 阻塞扫描 | **需修订**。10 事件 FIFO 不能保证 2–4 秒阻塞期间不丢事件，建议改为异步扫描。 |
| §5.5 文本与缓存同步 | “Enter 提交、Backspace 返回上一步”可以接受，但必须先修复手动编辑与扫描选择状态混用的问题。 |
| §5.6 内存占用 | **接受**。`UI_WIFI_SCAN_ITEM_MAX` 当前为 13，新增数组实际为 `13 × 33 = 429` 字节，不是约 1KB。 |
| §5.7 提交拆分 | **原则同意**。完成修订后按键盘布局、WiFi 配置、AI 聊天三个提交拆分。 |

## 3. 分项结论

| 功能 | 结论 | 说明 |
|---|---|---|
| 两个物理 Shift 键映射 | **部分通过** | 坐标修正有实测依据，但多 Shift 状态机需修复 |
| Alt 键语义 | **待产品决策** | 推荐临时符号层；当前仍表现为 Shift |
| SSID 手动输入 | **不通过** | 无法输入合法的 `+`、`-` 字符 |
| WiFi 扫描与选择 | **不通过** | 已有 SSID 时扫描入口不可达，且同步扫描存在 FIFO 风险 |
| `\b` 删除/返回约定 | **通过** | 当前提示和键盘返回路径合理 |
| AI 聊天发送后清空输入 | **通过** | 仅在成功发送并取得回复后清空，不会丢失失败请求草稿 |
| AI 查看模式直接输入 | **通过** | 可见字符会返回输入模式并保留首字符 |
| README 键盘布局 | **部分通过** | 物理布局与代码一致；Alt 说明应随最终语义更新 |
