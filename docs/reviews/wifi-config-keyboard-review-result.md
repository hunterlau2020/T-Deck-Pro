## 2. 本次 Findings

### 2.1 全量排空硬件 FIFO 会静默丢失除最后一个以外的字符

- **严重性**：High
- **位置**：`examples/pda2/peri_keypad.cpp:123-193`
- **触发场景**：两个或更多字符按下事件在一次 `keypad_loop()` 调用前已进入 TCA8418 FIFO，例如快速输入、页面刷新较慢或联网操作结束后处理积压事件。
- **证据**：
  - `while (keypad.available() > 0)` 会在一轮内取完全部硬件事件。
  - 每个字符仍写入同一个 `keypad_curr_val`，并仅设置同一个 `keypad_update` 布尔标志。
  - 应用层在 `keypad_loop()` 返回后只能调用一次 `keypad_get_val()`，因此只能取得最后写入的字符。
- **影响**：快速输入会随机少字；申请书声称的“持续排空 FIFO、扫描期间连按不丢事件”并未实现。
- **最小修复**：增加软件字符 FIFO。硬件事件排空时逐字符入队，`keypad_get_val()` 每次出队一个字符；或保持每轮只交付一个字符事件，不得在没有软件队列的情况下全量排空。

### 2.2 TCA8418 溢出标志未清除，首次溢出后修饰键会持续被重置

- **严重性**：High
- **位置**：`examples/pda2/peri_keypad.cpp:196-200`
- **触发场景**：TCA8418 FIFO 曾发生一次溢出，此后继续使用 Alt、Shift 或 Sym。
- **证据**：
  - 代码注释错误地将 `INT_STAT` 视为 read-to-clear，只读取寄存器后调用 `keypad_modifiers_recover()`。
  - 仓库驱动 `Adafruit_TCA8418::flush()` 及库示例均通过 `writeRegister(TCA8418_REG_INT_STAT, mask)` 清除中断状态。
- **影响**：`OVR_FLOW_INT` 保持置位时，每轮循环都会清除 `alt_pressed`、左右 Shift 和 `sym_lock`；一次溢出后修饰键功能可能持续失效，并不断输出恢复日志。
- **最小修复**：处理溢出后按 W1C 语义写回清除：

```cpp
keypad.writeRegister(TCA8418_REG_INT_STAT,
                     TCA8418_REG_STAT_OVR_FLOW_INT);
```

同时增加一次溢出后的 Alt、Shift、Sym 恢复回归测试。

### 2.3 `scanDelete()` 不能取消正在进行的异步扫描

- **严重性**：Medium
- **位置**：`examples/pda2/ui_deckpro.cpp:1818-1825`
- **触发场景**：Alt+Enter 开始扫描后立即退出 WiFi Config，再进入其他需要扫描 WiFi 的页面。
- **证据**：
  - 当前 `destroy4_1()` 将 `WiFi.scanDelete()` 当作停止扫描使用。
  - 当前 ESP32 Arduino 框架的 `WiFiScanClass::scanDelete()` 仅清除完成标志并释放结果内存，不调用 `esp_wifi_scan_stop()`，也不清除正在扫描状态。
  - 其他页面调用 `scanNetworks()` 时，若 `WIFI_SCANNING_BIT` 仍存在，会直接得到 `WIFI_SCAN_RUNNING`。
- **影响**：离开页面后旧扫描仍在后台运行，其他 WiFi 扫描入口可能暂时不可用；注释和生命周期状态与底层实际状态不一致。
- **最小修复**：退出活动扫描时调用 `esp_wifi_scan_stop()`，再执行 `WiFi.scanDelete()`；扫描结果复制完成后也应释放框架扫描结果。若不希望直接依赖 ESP-IDF API，则允许扫描自然完成，并保持全局扫描状态由统一管理器接管，不能伪装成已取消。

### 2.4 触摸切换输入框会静默丢弃未提交内容

- **严重性**：Medium
- **位置**：`examples/pda2/ui_deckpro.cpp:1637-1650`
- **触发场景**：
  1. 修改 SSID 后不按 Enter，直接触摸密码框。
  2. 修改密码后直接触摸 SSID 框。
- **证据**：焦点回调改变 `wifi_cfg_field` 后调用 `wifi_cfg_refresh()`；该函数使用旧的 `wifi_ssid`、`wifi_pass` 缓存覆盖两个 textarea。
- **影响**：用户看到焦点成功切换，但刚输入的 SSID 或密码被无提示回滚，可能最终保存错误凭据。申请书 §4.3 所称“保护未提交的手动输入”只覆盖重复点击当前框，不覆盖真正的字段切换。
- **最小修复**：切换焦点前将当前 textarea 同步到页面草稿缓存，或将“刷新字段标记/光标”和“从持久缓存重载文本”拆成两个函数。字段切换不应重写另一输入框内容。
