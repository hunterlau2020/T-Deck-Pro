**收紧 2 条（A- 的跟踪项，不挡采纳）**：
- **Grok-1（防"实现合同"被当垃圾桶）**：§2.5.1 三分法的滥用风险=把真 P1 重贴成"实现合同"以开工。Grok §5 已给缓解（判定看最小修复 + 属主签字），但建议**再加一条硬判据**：凡"最小修复需要改动**签名/回滚/密钥/TLS/变砖路径**等承重规范之一"→ 强制归协议/架构类（P0/P1），不得归实现合同。即给"实现合同"设一个**负面清单边界**，与 §5 承重不变量清单挂钩。

## 三、Claude 提案评估：**C（采纳绝大部分；唯「主审制」一条退回改写=P1 治理风险）**

Claude 提案诊断精准（5 个触发问题全部成立），且贡献了 Grok 没有的 4 个好机制：**A-（带跟踪项接受）**、**[Implementation Note] 命名**、**静默表仅限运行态实体**、**Max-3-Rounds 硬熔断**。这些应采纳。但有**一条必须改写**：

### P1（治理风险）：「主审制——旁审仅提供反例线索、不具独立阻断权」与 §0.2「证据 > 票数」直接冲突，可放过真 P0/P1

- **位置**：Claude 提案 触发问题5 + §1.x 表"§0.2 & §7.2 明确 Primary Reviewer（主审制），旁审不具独立阻断权" + 增补4 邻近段。
- **证据/反例（用本项目自己的历史击穿）**：
  1. **§0.2 是现行指南的承重原则**：「合入决定是证据标签的函数，不是 reviewer 数量的函数；任何多数派结论盖不过一个带反例的发现」。主审制把"阻断权"绑定到**身份**（主审）而非**证据**，正是 §0.2 明令废止的"按身份/票数定结论"。
  2. **OTA 签名自指 P1 实证多模型互补**：该 P1 由 Codex/Grok/Claude 命中，**qwen（本人）v4 轮漏审**（已在 `…-3eb6f7e-qwen.md` 第六节诚实登记盲点）。**若当时实行主审制且 qwen 是主审、其余旁审无阻断权 → 这个"合法清单不可构造"的 P1 会随 A 开工流入实现**。这不是假想——是刚发生的事。
  3. **8s WDT 误杀健康镜像 P1**（本人 v3 轮命中）同样是"某一模型先抓到"。单点主审=把全项目的 P0/P1 捕获率压到"主审一个人的召回率"。
- **影响**：后果 **A**（被压制的若是协议/架构 P0/P1 → 变砖/误回滚/泄密可流入实现）；可达性 **2**（需主审恰好漏掉旁审抓到的 P1——OTA 历史证明这**会**发生）；静默（被压制的 P1 不留痕）。坐标 **A/2/静默 → P1**。**P1 不可风险接受**（§4.2）。
- **两轴**：`VERIFIED`（DOC：提案文本 + §0.2 现行条文 + OTA 评审史三个结果文件）/ `VIOLATES`（§0.2 证据>票数；§0 原则 2）。
- **最小修复（改写而非删除——保留 Claude 想解决的"军备竞赛/一票否决"真问题）**：把"按**身份**分配阻断权"改为"按**证据严重级**分配阻断力"：
  - **任一 reviewer（主审或旁审）拿出带 `file:line`+反例的协议/架构 P0/P1 → 阻断**（证据>票数原样保留）；
  - **旁审的 P2/P3/实现合同/完备性意见 → 仅建议，不阻断、不单方面倒逼新版**（这正是 Claude 想根治的"4 票任一否决"——否决权收窄到"有据 P0/P1"，而非取消旁审资格）；
  - **主审 = 收口轮的 delta 协调人 + 实现合同清单的归并人**（职责），**不是** P0/P1 的唯一闸门；
  - 设 **Max-3-Rounds 熔断**：同主题拉扯满 3 轮仍无新协议/架构 P0/P1 → 属主强制裁决（A-/开工 or 拍板争议项），转《实现期待办》。
  - 一句话：**军备竞赛的解药是"严重级纪律 + delta 锁定 + 轮次熔断"，不是"取消旁审的 P0/P1 阻断权"**。前者杀掉空转，后者会漏掉真雷。

### 其余 Claude 条款：采纳，但 2 条须加边界

- **Claude-2（静默表禁用须留口子）**：增补2.1"文档（DOC/SPEC）一律查有声表"方向对（文档没有串口日志是载体属性，不该因此上调），但**措辞过宽**——签名自指 P1 恰恰是"静默"的（所有合法清单验签失败、无差异化报错），却仍是 P1。**修正**：禁用的是"**假想级联上调**"（"若实现者写错→堆损坏→无日志→查静默表升 P1"），**不是**"设计正文**确定性**自相矛盾/必不可构造/必变砖"——后者无论有声静默都是 P0/P1。即：静默表上调规则不适用于"靠假设未来实现错误"的链条；但适用于"设计正文已唯一确定的运行态后果"。
- **Claude-3（A- 适用面）**：A-（带跟踪项接受）建议**同时适用设计稿与代码**，但**钉死语义**：A- = "无阻断(P0/P1)，仅含应修(P2)/Nit/实现合同，**免再发一轮评审**，跟踪项绑实现 commit 的 L2/G-合入或 `issue_list.md` 台账"。对代码，A- 不得削弱"A 不挂必修项"——必修项=阻断=P0/P1；P2 应修本就走台账（§4.2 三级标签），A- 只是给它一个显式名字，避免"P2→只能 C"的误用。
