## 1. `423b312` — PenPal Back-press 栈溢出（P0，每次必现）

**根因核实准确**：
- `pp_state_t` ≈ 15 KB（24 mailbox rows + 16 topics + 64 letters + scratch）。
- `pp_destroy` 内 `pp = pp_state_t()` 会在栈上物化整个 ~15 KB 临时对象再拷贝赋值；loopTask 栈共 8 KB，任何调用深度均必触发栈金丝雀，与串口证据 `Stack canary watchpoint triggered (loopTask)` 吻合。
- 第一轮修复（`lv_async_call` 延迟 pop）后仍崩溃，正确定位爆栈与调用深度无关，而是 `pp_state_t()` 本身。

**修复正确**：
- `pp_state_reset()` 逐字段原地复位；数组逐元素值初始化，最大单元素临时 `pp_topic_t` ≈ 370 B，安全。
- 字符串通过元素析构（`= pp_*_t{}`）释放，不 memset，符合 §10 规则。
- 代码核查：`pp_state_reset()` 覆盖 `pp.pals`、`pp.rows`、`pp.topics`、`pp.letters`、`pp.idem_snap`（`pp_send_req_t{}`）、`pp.send_lock`、各分页/选择索引等全部成员，无遗漏字段。
- `[PenPal] destroy done` 串口标记：便于回归确认，无副作用。

**设计细节正确**：
- 保留 `lv_async_call` 延迟 pop：点击事件栈先回退再跑拆链，有益（避免 LVGL 重入）；双击重入由 `scr_mgr_pop` 的 `top==root` 守卫兜底。
- `pp_back_cb` 中 `s_pp_active = false` 同步执行（在 async_call 调度之前）：确保若在延迟 pop 实际执行前有结果到达，也能正确被 stale-drop 拒绝。`pp_exit()` 内 `s_pp_active = false` 再次赋值无害。

## 3. `bfa7a16` — 菜单手势边沿触发（每次滑动恰好一页）

**根因正确**：
- `indev_get_gesture_dir` 每 30ms 轮询 `lv_indev_get_gesture_dir`，LVGL 的 `gesture_dir` 从手势检测起持续保持到下一次按下才复位（`lv_indev.c` 按下起点 reset；`gesture_sent` 每次按压单发）→ 一次滑动期间回调连发 N 次。
- 两页时边界钳位（0↔1）掩盖了连发；三页即暴露，一次滑动跳两页。

**修复正确**：
- 静态变量 `s_last_gesture_dir` 记录上次值，仅在 `NONE → LEFT/RIGHT` 跃迁时触发一次回调。
- `if(ui_get_gesture_dir)` NULL 守卫：菜单 exit 后该指针置 NULL，防止非菜单页发生手势时空调用函数指针，必要。

**边界情况推理**：
- 用户在非菜单页滑动后进入菜单，`s_last_gesture_dir` 可能持有非 NONE 值。但退出菜单时手指已抬起，LVGL 会在下次按下时复位 `gesture_dir` 为 `NONE`，所以进入菜单后第一次轮询 `dir` 将是 `NONE`，`s_last_gesture_dir` 随之更新为 `NONE`——实际不会丢失第一个手势，推理自洽。
