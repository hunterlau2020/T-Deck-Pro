## 核对结果

- `423b312`：逐字段核对 `pp_state_reset()` 覆盖了 `pp_state_t`（`ui_penpal.h`）
  的**全部**字段，与旧的 `pp = pp_state_t()` 语义等价；数组一律逐元素
  `= T{}`（含 `string` 成员的元素走正常析构/重建），单元素最大约
  370B（`pp_topic_t`），确认不会在 8KB loopTask 栈上物化 ~15KB 临时对象。
  `idem_snap = pp_send_req_t{}` 单独复位，体量小（~100B），安全。
- `pp_back_cb` 改为 `lv_async_call(pp_pop_async, NULL)` 延迟 `scr_mgr_pop`；
  `s_pp_active` 仍同步置 false，避免延迟窗口内到达的异步结果被误消费。
  复核了 `scr_mgr_pop`（`ui_scr_mrg.c:229`）的
  `scr_stack_top == scr_stack_root` 卫兵：PenPal 是从主菜单
  `scr_mgr_push` 直接压入的二级栈（[menu(root), penpal(top)]），双击
  Back 产生的第二个排队 pop 到达时栈顶已回落到 root，卫兵会直接拒绝，
  确认无害。
- `bfa7a16`：`indev_get_gesture_dir` 边沿触发（`NONE -> LEFT/RIGHT` 才回调
  一次）与 `ui_get_gesture_dir` 判空，逻辑与 LVGL `gesture_dir` 直到下次
  按下才复位的行为吻合，能修复三页菜单单次滑动跨页的问题；非菜单页时
  函数指针为 NULL，判空后不再野调用。
- `e70b591`：`lan[24]` 足够容纳 `WiFi.localIP().toString()`
  （IPv4 最长 15 字符+`\0`），`msg[128]` 容纳两段 IP 文本不溢出；
  `strncpy`+手动补 `\0` 的收尾方式正确。

未发现新增缺陷；三处改动的根因分析与代码改动一致。
