# allinone AI 配置与对话交互复审结果

- **评审日期**：2026-08-16
- **评审对象**：[`allinone-design.md`](../allinone-design.md) 中“AI 对话屏交互”“AI 配置屏交互”及关联流程
- **参考实现**：`examples/pda2/ui_ai_chat.cpp`、`ui_ai_cfg.cpp`、`openai_api.cpp`
- **评审结论**：**退回修订**

## 1. Findings

### 1.1 首次发送失败后没有直达配置路径，且退出会破坏已输入问题

- **严重性**：High
- **位置**：`docs/allinone-design.md:160-163`
- **触发场景**：首次进入 AI 对话页，输入完整问题后按 Enter，但 API Key、模型或 WiFi 尚未配置。
- **证据**：
  - 设计只要求显示 `Set WiFi / Set AI Key`，AI 配置入口仍位于菜单项 `8 AI Cfg`。
  - 对话输入态的 Backspace 优先删除字符，只有输入框为空时才能退出。
  - 因此用户必须逐字删除刚输入的问题，退出到菜单，完成配置后再重新输入。
- **影响**：最常见的首次使用流程会造成明显返工；提示只说明缺什么，没有提供完成任务的动作路径。
- **最小修复**：
  1. 缺少配置时直接 `scr_mgr_push(SCREEN_AI_CFG_ID)`，保留对话草稿。
  2. 配置保存后返回 AI 对话页并恢复草稿，由用户再次确认发送。
  3. WiFi 未配置时同理跳转 WiFi 配置页，或至少提供明确的快捷键入口。

### 1.2 AI 配置页用“清空字段”承担返回导航，修改和取消流程会毁坏数据

- **严重性**：High
- **位置**：`docs/allinone-design.md:165-166`
- **触发场景**：用户已从端点进入模型或 API Key 字段，发现上一字段输入错误；或者编辑过程中希望放弃修改。
- **证据**：
  - Enter 只向后切换字段。
  - Backspace 在字段非空时只删除字符，字段为空后才能返回上一字段。
  - 设计没有独立的“上一字段”“取消编辑”或“不保存退出”动作。
- **影响**：
  - 返回上一字段必须先删除当前字段全部内容。
  - 用户无法在保留现有配置的前提下检查或修改上一字段。
  - 误入编辑或中途放弃时，没有清晰的取消语义。
- **最小修复**：采用与 WiFi 配置相同的显式状态设计；例如 Tab/Alt+方向键切换字段，Backspace 只删除，Esc/指定组合键取消并恢复进入页面时的快照，Save 明确提交全部字段。

### 1.3 最后一个 Enter 无条件保存并退出，错误配置会直接覆盖可用配置

- **严重性**：High
- **位置**：`docs/allinone-design.md:165-168`、`docs/allinone-design.md:222`
- **触发场景**：端点格式错误、模型为空、Key 误输或自定义服务与 OpenAI 响应格式不兼容。
- **证据**：
  - 设计规定最后一个字段按 Enter 后立即写 NVS 并退出。
  - 没有本地格式校验、必填校验、连接测试、认证测试或“测试成功后保存”契约。
  - 没有说明失败时保留旧配置、保留草稿还是回滚。
- **影响**：一次输入错误就会覆盖已知可用配置；用户只能在 AI 对话页看到模糊失败，再返回配置页逐字段排查。
- **最小修复**：
  1. 编辑时保存原配置快照，新值先进入草稿。
  2. 校验 HTTPS URL、非空模型和非空 Key。
  3. 提供 `Test` 与 `Save` 两个明确动作；测试失败不覆盖 NVS。
  4. 保存成功后显示结果，并保留一键恢复默认端点或旧配置的能力。

### 1.4 自签名 TLS 开关在无触摸产品中没有可达的键盘流程

- **严重性**：High
- **位置**：`docs/allinone-design.md:91-92`、`docs/allinone-design.md:165-168`
- **触发场景**：用户配置使用私有 CA 或自签名证书的自定义端点。
- **证据**：
  - TLS 章节要求在 AI Cfg 屏勾选 `Trust self-signed`，并写入 `ai_insecure=1`。
  - AI 配置交互和文件设计只定义端点、模型、API Key 三个字段，没有第四个 TLS 字段及其键盘操作。
  - allinone 已明确移除触摸，checkbox 的点击路径不可用。
- **影响**：文档承诺的自定义端点恢复路径实际不可达；若实施者自行补一个触摸开关，则会重复出现 WiFi 早期“控件存在但目标输入设备不能操作”的问题。
- **最小修复**：把 TLS 模式纳入配置状态机并提供键盘可达的枚举字段；默认保持 CA Verify，切换到 Insecure 前显示明确风险确认，页面和对话页持续显示警告，并明确该选择是仅本次会话还是持久化设置。

### 1.5 同步请求会冻结界面最多 30 秒，发送状态无法取消或离开

- **严重性**：Medium
- **位置**：`docs/allinone-design.md:161-162`、`docs/allinone-design.md:275`
- **触发场景**：模型响应缓慢、网络不稳定、服务端限流或请求直到超时。
- **证据**：
  - 设计明确接受 `openai_chat()` 同步阻塞 15–30 秒。
  - 请求在 UI 流程内执行，`Thinking...` 刷新后主线程不能继续处理页面事件。
  - 设计没有发送代次、取消、离页、迟到结果或阻塞期间键盘队列处理规则。
- **影响**：用户无法取消请求、退出页面或修正误发送；按键可能在请求结束后集中作用于回答页或下一页面。
- **最小修复**：使用工作任务异步请求；发送态屏蔽普通输入但保留 Cancel/Back，按请求代次丢弃取消后或离页后的迟到结果，完成时仅由 LVGL 线程更新 UI，并清理发送期间积压按键。

### 1.6 所有失败被合并为通用提示，用户无法采取正确恢复动作

- **严重性**：Medium
- **位置**：`docs/allinone-design.md:162-163`
- **触发场景**：NTP 未同步、TLS 校验失败、401 Key 错误、402/429 配额或限流、404 模型不存在、超时、服务器 5xx、响应 JSON 不兼容。
- **证据**：
  - 设计只规定 `Set WiFi / Set AI Key`，参考实现失败时显示 `AI error - check cfg / WiFi`。
  - 未定义 HTTP 状态、TLS/时间错误和解析错误到用户提示及恢复动作的映射。
- **影响**：用户面对不同故障只能反复修改配置，甚至可能被错误引导去启用 Insecure TLS。
- **最小修复**：定义错误分类表，至少区分：
  - 未联网/时间未同步；
  - TLS 证书错误；
  - 401/403 认证错误；
  - 402/429 配额或限流；
  - 404 模型或端点错误；
  - 超时/服务端错误；
  - 响应格式不兼容。

每类提示应附带 `Retry`、`Open WiFi Cfg`、`Open AI Cfg` 或 `Cancel` 中的适用动作，并保留原问题草稿。

### 1.7 “AI 对话”实际是无上下文的单轮问答，产品语义未明确

- **严重性**：Medium
- **位置**：`docs/allinone-design.md:13-14`、`docs/allinone-design.md:160-163`、`docs/allinone-design.md:223`
- **触发场景**：用户查看回答后继续输入“再详细一点”“把第二点展开”等追问。
- **证据**：
  - `openai_chat()` 的请求体只包含当前一条 user message。
  - 回答后输入任意字符会退出浏览态并开始新输入，但上一轮问答不会加入下一次请求。
  - 设计没有“新会话”“继续对话”“清除上下文”或上下文长度策略。
- **影响**：界面名称和交互暗示支持连续对话，实际追问无法引用上文，容易被误判为模型能力问题。
- **最小修复**：明确选择其一：
  - v1 定义为“AI 单轮问答”，修改页面名称和提示；
  - 实现有限轮次上下文，并提供 New Chat/Clear、上下文截断及内存上限策略。

### 1.8 API Key 默认明文编辑，且固定掩码错误暗示仅支持 OpenRouter

- **严重性**：Medium
- **位置**：`docs/allinone-design.md:167-168`
- **触发场景**：用户在公共环境编辑 Key，或配置非 OpenRouter 服务。
- **证据**：
  - 设计明确规定编辑时 textarea 显示完整明文。
  - 标签固定显示 `sk-or-v1-***`，不能正确表示其他供应商 Key，也不能帮助用户区分当前保存的是哪一个 Key。
  - 设备使用墨水屏，敏感文本还可能在刷新后留下可见残影。
- **影响**：增加旁观泄露风险；固定前缀又会让自定义端点用户误以为 Key 未正确保存。
- **最小修复**：默认密码模式显示；提供需要明确按键操作的临时 Reveal；摘要使用通用形式并只显示末尾 4 位，例如 `Key: ****a1b2`；离开编辑态后执行全刷清除残影。

### 1.9 “可配置任意 OpenAI 兼容端点”与输入能力、长度和恢复操作不匹配

- **严重性**：Medium
- **位置**：`docs/allinone-design.md:30-31`、`docs/allinone-design.md:167-168`
- **触发场景**：输入含大写字母、查询参数、IPv6 地址、较长 Key 或复杂模型 ID 的自定义服务配置。
- **证据**：
  - 设计将字段描述为“小写 + `0-9 . : / - _`”，但自定义 URL、模型 ID 和 API Key 的合法字符集合并不限于这些字符。
  - 没有规定最大长度、超长提示、整字段清空、恢复默认值或从预设中选择。
  - 在只有 Backspace 的尾部编辑模型下，修正长 URL 或 Key 中间的一处错误需要删除其后的全部字符。
- **影响**：产品宣称的兼容范围大于实际可输入范围；复杂配置的首次录入和纠错成本过高。
- **最小修复**：明确各字段允许字符与最大长度；超限时立即反馈且不得静默截断；提供 Clear、Restore Default 和常用端点/模型预设；若不支持光标编辑，应提供整字段替换或分段编辑方式。

## 2. 通过项

- AI Cfg 已作为独立菜单项，可从主菜单到达。
- 对话输入不再占用普通字母作为配置快捷键，避免正文输入冲突。
- 回答浏览时输入可见字符会回到输入态，不会静默丢弃该字符。
- 成功发送后清空已消费的输入，使浏览态 Backspace 的含义较明确。
- 已要求按 UTF-8 和实际字体宽度处理回答换行，方向正确。
- 默认启用 CA 验证，并考虑了系统时间对 TLS 的前置要求。

## 3. 建议的产品状态机

### 3.1 AI 配置页

| 状态 | Enter | Backspace | 字段切换键 | Cancel | Save/Test |
|---|---|---|---|---|---|
| 编辑端点/模型/Key/TLS | 编辑字段，不隐式保存整页 | 仅删除字符 | 不修改内容地切换字段 | 恢复进入页时快照并退出 | 校验草稿；测试失败不写 NVS |
| 测试中 | 无操作 | 无操作 | 无操作 | 取消请求 | 成功后允许 Save |
| 测试失败 | 重试 | 返回编辑 | 切到关联字段 | 放弃修改 | 显示明确错误 |
| 保存完成 | 返回对话页 | 返回菜单 | — | — | 恢复原对话草稿 |

### 3.2 AI 对话页

| 状态 | Enter | Backspace | 可见字符 | Cancel/Back |
|---|---|---|---|---|
| 输入 | 发送；缺配置则带草稿进入配置 | 删除；空框时退出 | 追加 | 退出并明确草稿策略 |
| 发送中 | 无操作 | 无操作 | 屏蔽 | 取消请求并清空积压按键 |
| 回答浏览 | 下一页；末页给出 New/Retry 提示 | 上一页；首页回输入 | 回输入并追加，但保留回答供返回 | 返回输入或退出 |
| 失败 | Retry | 回输入 | 回输入并追加 | 打开对应配置页或退出 |
